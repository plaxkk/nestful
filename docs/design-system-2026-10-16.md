# Nestful 全页视觉与交互规范

2026-10-17 更新：底部导航与首页信息层级以 [日常布局与导航设计](information-architecture-2026-10-17.md) 为准；此文的颜色、字体与共用控件规范继续沿用。

以已确认的“家的日常”首页为基准，其他页面围绕一个当前家庭展开；多个家庭通过首页切换，不在各业务页并列展开。

## 视觉规范

- 底色暖纸白 `#faf7f1`，内容表面 `#fffefa`，正文 `#26392e`，辅助文字 `#6c746b`。
- 主操作森林绿 `#365b44`，轻提示灰绿 `#ecf0e7`，摘要/注意事项暖沙色 `#f1e6d3`，辅助强调陶土色 `#925938`。
- 使用系统字体（优先 PingFang SC），页面标题 50rpx/600，分区标题 33rpx/600，正文约 28–31rpx；避免大面积粗体。
- 页面横向留白 44rpx，小屏 32rpx；分区间距 32rpx；主要按钮最小高 96rpx，文字按钮最小高 88rpx。
- 颜色、表单、按钮、空状态、错误与加载状态集中在 `app.wxss`。页面样式只定义自身布局，首页保留已确认的独立布局。

## 信息结构

| 页面 | 默认先看到 | 按需展开 |
| --- | --- | --- |
| 活动 | 近期安排、时间地点、我的回应入口 | 独立详情中回应、分工、分享；管理操作另行展开 |
| 提醒 | 当前家庭提醒清单、状态、接收/完成信息 | 新增或修改提醒计划 |
| 账本 | 本月结余、收入支出、最近记录 | 记账、共同目标；分类与分摊分析 |
| 家庭记录 | 分类筛选、已有资料/账号说明/记忆 | 新增记录；日期、人物、地点等补充信息 |
| 家庭 | 当前家庭、家人、待审批申请 | 邀请、邀请记录、家庭设置；点击成员查看或编辑资料 |
| 创建/加入 | 明确的单一任务和隐私同意 | 校验邀请成功后才填写称呼及确认加入 |
| 隐私与帮助 | 可阅读的隐私说明、数据处理范围和入口 | 复制反馈定位信息、微信反馈、本机退出登录 |

## 交互约定

1. 新增表单默认收起；同一区域只展示一个编辑任务。取消保留当前填写，保存成功后收起并刷新列表；失败保留表单内容。
2. 账目、目标、记录不填入会被误保存的示例；示例只出现在占位文字中。记忆不默认标记某位家人。
3. 日期/时间使用原生选择器。每日两/三次的固定时刻直接说明，避免把计划起点误解为全部提醒时刻。
4. 保存期间禁用重复提交。跨家庭的迟到响应不能覆盖当前内容，业务页显示当前家庭名称。
5. 管理与普通成员继续遵循服务端权限。退出、归档、移除、停止计划、账目作废等原有确认保留。
6. 可选文字/链接未填写时不发送空字符串；数据库返回的空续费、空负责人值在修改请求中省略，避免普通记忆、账目或提醒修改失败。转存记忆、退出登录、撤销邀请等无业务字段的 POST / DELETE 请求也显式发送 `{}`，保持合法 JSON 请求体。
7. 邀请先校验，再显示加入表单；修改邀请码立即清除旧校验结果；待审批时不能访问家庭内容。
8. 微信通知需接收人单次授权；记录只保存文字与链接；账号说明不保存密码或恢复密钥。界面不承诺未提供的能力。
9. 生日在新增提醒、修改计划、成员资料中共用 `birthday-input`。先选公历/农历；公历使用日期选择器，农历使用独立月日列（含三十）和闰月开关，不用公历日期控件承载农历。切换历法清空日期，要求重新选择，避免把同一组数字静默改成另一种生日。列表明确显示历法；闰月生日仅在对应闰月出现时提醒。提醒计划的生日设置独立保存，不会自动改写成员资料。

## 验证方式

- `npm run release:local-gate`：类型、构建同步、模板事件、MVP 路径、首页、首屏性能与新增设计回归。
- `npm run test:postgres`：一次性本机 PostgreSQL 上的真实 API / 数据权限回归。
- `npm run design:fixture`：启动仅绑定 loopback 的临时数据库与真实 API；退出进程后清理数据库。测试会话上下文默认写到 `/private/tmp/nestful-design-context.json`，仅包含本机测试凭据，禁止用于线上数据库。
- 微信开发者工具原生自动化：实际点击、输入、触发日期选择、保存及读取页面状态；外部微信群发送和通知实际送达仍属于真机平台验收。
