# 小程序分享配置排查

2026-10-22，用户反馈微信正式版 0.4.7 中只有“活动”“家庭”可复制链接，其余三个 tab 置灰，首页“转发给朋友”也置灰。本次检查以当前仓库代码及其生成的 JavaScript 为准。

## 已确认的遗漏与修复

- `988b841` 为“提醒”“记录”补上页面级 `onShareAppMessage`。
- 本次继续检查发现从首页进入的“家庭账本”也缺少该回调，已补齐。
- 三处均复用 `publicProductShare`，返回固定公开介绍页，不将提醒、健康、账目或记录内容放进产品卡片。
- 首页在本次修改前已注册该回调，TS、生成 JS 与原生模拟器均能执行。没有发现主动调用 `hideShareMenu` 的代码，也没有据猜测修改首页菜单状态。

## 当前分享目标

| 页面 | 分享目标 |
| --- | --- |
| 首页、提醒、记录、账本 | 固定公开介绍页 `/pages/about/index` |
| 产品介绍 | 公开介绍页；现有朋友圈分享配置保留 |
| 活动列表菜单 | 首页 |
| 活动详情菜单 | 对应家庭的具体活动 |
| 已准备的活动分享按钮 | 该活动的分享路径，保留原邀请及审批流程 |
| 家庭页 | 已准备的加入路径；未准备时回到首页 |

家庭邀请和活动详情原有的成员访问控制没有改变。

## 验证结果

1. 补充账本分享检查后，修改前测试因 `ledger must register a page share handler` 失败；补齐后通过。
2. `npm run miniprogram:design-flows` 检查五个导航目标的分享注册、普通产品卡片的数据边界，以及活动菜单、活动按钮与家庭邀请的目标路径。
3. `npm run release:local-gate` 完整通过，包含类型检查、生成 JS 同步、模板绑定、MVP、首页、生日、设计和首屏流程。
4. 原生模拟器通过实际 `family-nav` 组件走完：首页 → 提醒 → 活动 → 记录 → 家庭 → 首页，再由首页进入账本并返回。八次页面检查均存在有效分享回调及标题、图片和预期目标，最后恢复原页面栈。没有发送消息或创建、修改家庭数据。

这些检查验证了代码注册、分享返回内容和页面切换，不等于已在手机上点击微信系统菜单的“复制链接”。

## 正式版边界

仓库没有可对应到正式版 0.4.7 的不可变上传快照，因此不能仅凭版本号确认它的首页源码，也不能把本机结果当作该正式版的验收结果。

本次未上传、提交审核或发布小程序。用包含上述修复的新代码包进行手机体验版验收时，应分别进入五个 tab 和账本，检查“转发给朋友”和“复制链接”，再检查经过活动、家庭页返回首页的情况。发布后需在手机确认实际运行版本与验收包相同。
